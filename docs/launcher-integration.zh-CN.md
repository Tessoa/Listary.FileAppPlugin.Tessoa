# 启动器接入 tessoa

[English](launcher-integration.md)

本文写给启动器、搜索工具、文件对话框增强工具（Listary 这一类软件）的开发者，说明怎样与
[tessoa](https://github.com/Tessoa)（Windows 上的 GPU 加速文件管理器）配合。

tessoa 的界面是自己绘制的，没有 UI Automation 树，也没有标准控件，读地址栏、模拟按键这些
常规办法都用不上。tessoa 为此提供了两个稳定的接口：

| 方向 | 接口 | 用途 |
|---|---|---|
| 读 | 每个进程一条只读命名管道 | 查询某个窗口显示的是哪个文件夹，或列出它的所有标签页 |
| 写 | `tessoa.exe` 的命令行参数 | 在程序级、窗口级或标签页级打开文件夹、定位文件 |

两者都只在 Windows 上提供。参考实现是 Listary 插件，即本仓库（C#，MIT）。

---

## 1. 认出 tessoa 窗口

所属进程映像为 `tessoa.exe` 的顶层窗口，就是 tessoa 窗口。

```
GetWindowThreadProcessId(hwnd)  ->  pid
QueryFullProcessImageName(pid)  ->  以 "\tessoa.exe" 结尾（不区分大小写）
```

一个 tessoa 进程可以有多个窗口。请始终把窗口句柄（HWND）和进程号一起保存：下文所有接口都接受
HWND，回答针对的是用户正在看的那个窗口，而不是随便哪个 tessoa 窗口。

tessoa 还会启动同名的辅助进程（例如带 `--shell-menu-host=` 参数的右键菜单宿主），它们没有可见的
顶层窗口。从窗口出发而不是从进程列表出发，就不会被它们干扰。

## 2. 读：查询管道

### 管道名

```
\\.\pipe\tessoa.q.<pid>
```

管道名里带进程号，所以从窗口句柄可以直接找到对应的管道，便携版和安装版同时运行也不会认错。
没有窗口句柄时，可以枚举 `\\.\pipe\` 下以 `tessoa.q.` 开头的管道，找出正在运行的实例。

这条管道只读，只接受下面两种查询，不会让 tessoa 执行任何操作。查询不会把窗口提到前台，也不会
在 tessoa 的日志里留下记录。

### 帧格式

每次连接只传一个请求、一个回答，两者格式相同：

```
[4 字节小端长度][UTF-8 正文]
```

连接、写一帧、读一帧、关闭。请设置超时：整个过程 1 秒已经很宽裕，因为回答来自 tessoa 预先
备好的一张表，不需要等它的界面线程。管道忙（`ERROR_PIPE_BUSY`）时，最多等 200 毫秒左右再试。

### 请求正文

按行组织，每行是「键 空格 值」，以 `\n` 结尾。

```
v 1
op query-cwd
hwnd 123456
```

| 行 | 含义 |
|---|---|
| `v 1` | 必需，表明这是 tessoa 的协议。 |
| `op <名称>` | `query-cwd` 或 `query-tabs`。 |
| `hwnd <十进制>` | 可选，要查询的窗口。不给时回答 tessoa 的聚焦窗口。解析不出数字的值按没给处理，所以请写成普通的十进制整数。 |

不认识的行会被忽略，以后的版本加行不会影响你。

### `op query-cwd`：窗口的当前文件夹

回答正文是一个 UTF-8 编码的绝对路径，末尾没有换行。

**长度为 0 的回答是正常回答**，意思是「这个窗口没有可报的文件夹」：当前标签页是起始页、
「此电脑」、预览、终端或设置页，或者句柄不是 tessoa 窗口。请当作「这里没有」处理，不要退回
到别的窗口，也不要猜。指名查询某个窗口时，tessoa 自己也绝不会拿另一个窗口的文件夹来回答。

tessoa 刚启动的一两秒里，第一个窗口还没建出来，回答同样是空的。

### `op query-tabs`：窗口的所有文件夹标签页

需要文件应用接口 2（见第 4 节）。回答形如：

```
api 2
tab 17 c D:\Work
tab 23 v D:\Photos\2026
tab 31 b C:\Users\me\Downloads
```

- 第一行恒为 `api <n>`，即使一页都没有、窗口认不出也一样。
- 之后每个文件夹标签页一行：`tab <编号> <位置> <路径>`。路径是这一行剩下的全部内容，可以含空格。
- `<位置>`：`c` 是当前页（聚焦的标签组里排在前台的那一页）；`v` 是另一个可见标签组的前台页
  （tessoa 可以把一个窗口分成几组）；`b` 是后台页。
- 当前页排第一，其余按布局顺序、组内按标签顺序。
- 没有文件夹的页（预览、终端等）不列出。
- `<编号>` 是 tessoa 给这一页的编号，页面跳转时不变；把它传回去，就能在指定的那一页里打开东西
  （第 3 节）。编号只在进程存活期间有效。

旧版 tessoa 对 `query-tabs` 回答**空帧**。不用启动任何东西，就能据此分出新旧版本。

### 示例（C#）

```csharp
static string Query(int pid, IntPtr hwnd, string op)
{
    using var pipe = new NamedPipeClientStream(".", "tessoa.q." + pid, PipeDirection.InOut);
    pipe.Connect(1000);
    byte[] body = Encoding.UTF8.GetBytes($"v 1\nop {op}\nhwnd {hwnd.ToInt64()}\n");
    pipe.Write(BitConverter.GetBytes(body.Length), 0, 4);
    pipe.Write(body, 0, body.Length);
    pipe.Flush();

    byte[] head = ReadExactly(pipe, 4);
    int length = BitConverter.ToInt32(head, 0);
    return length == 0 ? "" : Encoding.UTF8.GetString(ReadExactly(pipe, length));
}
```

`ReadExactly` 循环调用 `Read`，直到读满指定字节数。连不上说明那个进程没在服务（没运行或正在
退出）；连上了但回答为空，说明进程在运行、只是没有可报的内容。诊断时请把这两种情况分开。

## 3. 写：命令行参数

要让 tessoa 跳到某处，就带参数启动 `tessoa.exe`。如果 tessoa 已经在运行，新进程会把请求交给
正在运行的那个，几毫秒内退出；如果没在运行，新进程自己就成为 tessoa 并打开目标。

每个参数（连同参数名）作为**一个**带引号的参数传入，这样含空格的路径不会被拆开：

```
tessoa.exe "--open-window=D:\My Projects"
```

### 动作

| 参数 | 效果 |
|---|---|
| `--open-window=<文件夹>` | 显示这个文件夹。 |
| `--reveal-window=<路径>` | 显示它所在的文件夹，并选中这个文件或文件夹、滚动到可见。 |

参数名是历史遗留，tessoa 并不总是开新窗口。不带落点修饰（见下）时，它会优先复用已有的页：

1. 某个标签组的前台页已经是这个文件夹：把焦点给这个组。
2. 否则，如果有后台页是这个文件夹：把那一页切到前台。
3. 否则，在当前窗口聚焦的标签组里新开一页。
4. 只有一个窗口都没有时，才新建窗口。

所以同一个请求重复发，不会堆出重复的标签页。

路径必须是绝对路径，而且必须存在；`--open-window=` 必须给文件夹。定位文件时，tessoa 会等慢速
文件夹加载完，并刷新列表已经过时的页，所以刚刚创建的文件也能找到。

### 落点修饰：窗口级与标签页级

需要文件应用接口 2。另加下面**一个**参数：

| 参数 | 层级 | 效果 |
|---|---|---|
| `--in-window=<hwnd>` | 窗口级 | 复用规则同上，但只在这个窗口内。 |
| `--in-tab=<hwnd>` | 标签页级 | 让这个窗口的当前页原地跳过去。 |
| `--in-tab=<hwnd>:<编号>` | 标签页级 | 把这个编号（来自 `query-tabs`）的页切到前台，再原地跳过去。 |

```
tessoa.exe "--open-window=D:\Work" "--in-tab=123456"
tessoa.exe "--reveal-window=D:\Work\notes.txt" "--in-tab=123456:23"
```

标签页级跳转和在 tessoa 里点一个文件夹的效果一样：会记入这一页的历史，按「后退」能回到原来的
文件夹。目标已经在显示时，什么都不动，请求照样算成功。

tessoa 处理请求时如果目标已经不在了，会退一级，而不是失败：

| 请求的层级 | 退到 | 什么时候 |
|---|---|---|
| 标签页级 | 窗口级 | 那一页已经关了，或者那一页不能显示文件夹（预览、终端等）。 |
| 窗口级 | 程序级 | 那个窗口已经关了。 |

用户在 tessoa 里切换显卡时窗口句柄会变，你之前存下的句柄可能已经失效；退一级之后仍然会落在
合理的位置。

**在动手的那一刻再指定「当前页」。** 请用 `--in-tab=<hwnd>`，而不是事先记下当前页的编号：用户
在你的搜索框里打字的那几秒，可能已经切了页。

### 退出码

| 退出码 | 含义 | 怎么处理 |
|---|---|---|
| `0` | 请求已送达，或者这个进程自己成了 tessoa 并打开了目标。 | 完成。 |
| `1` | 正在运行的 tessoa 没有接受请求，通常是它比你启动的那个可执行文件旧，不认识落点修饰。 | 去掉落点修饰再试一次。 |
| `2` | 参数无效：路径缺失或不存在、给 `--open-window=` 传了文件、落点修饰的值认不出、只有落点修饰没有动作、同时给了两个落点修饰。 | 不要重试。 |

如果 tessoa 原本没在运行，你启动的那个进程**就是** tessoa，会一直运行下去，不要等它退出。等几秒，
如果它还活着，就当作成功。Listary 插件等的是 3.5 秒。

## 4. 能力探测

不要为了试探某个参数能不能用，就去启动一个版本未知的 tessoa：旧版会忽略不认识的参数，照常开窗，
试探这个动作本身就改变了用户的屏幕。

| 能力 | 怎么判断 |
|---|---|
| 读当前文件夹（`query-cwd`） | 管道存在即可。tessoa 0.22.0 起提供。 |
| `--open-window=` / `--reveal-window=`（接口 1） | 可执行文件版本资源的 `Comments` 字段恰好是 `tessoa-file-app-api=1`。直接从文件里读，不必启动。 |
| `query-tabs`、`--in-window=`、`--in-tab=`（接口 2） | 向**正在运行的**进程发 `query-tabs`。第一行是 `api 2` 或更高即支持；回答空帧即不支持。 |

`Comments` 标记有意保持为 `=1`，因为已有的接入是按全等比较的。接口 2 改由正在运行的进程报告，
这样也更准确：用户换了可执行文件却没重启 tessoa 时，以正在运行的进程为准。

## 5. 找到 `tessoa.exe`

建议按这个顺序：

1. 用户明确配置的路径。路径无效时报错，不要悄悄改用另一份安装。
2. 见过的 tessoa 窗口所属的可执行文件（第 1 节）。
3. HKCU、再 HKLM 下的 `App Paths\tessoa.exe`，64 位和 32 位注册表视图都要看。
4. `%LOCALAPPDATA%\tessoa\tessoa.exe`，即默认安装位置。

便携版可以放在任何地方，所以用户配置排在最前面。

## 6. 不写代码先自测

tessoa 自己的命令行也能回答同一条管道：

```
tessoa.exe --print-cwd                      # 任一运行中实例的聚焦窗口
tessoa.exe --print-cwd=<pid>:<hwnd>         # 指定某个窗口
tessoa.exe --print-cwd --print-cwd-out=x.txt
```

退出码 `0` 表示打印了路径，`1` 表示没有可报的内容或没在运行，`2` 表示参数无效。正式版是窗口程序，
没有控制台，脚本里请用 `--print-cwd-out=` 取结果。

## 7. 几条值得守住的规矩

- **空就是空。** 绝不拿别的窗口的文件夹、或者记下来的旧文件夹来顶替。
- **留着 HWND。** 查询用户正在看的那个窗口，而不是那个进程。
- **答案不要缓存太久。** 用户每跳一次，文件夹就变一次。你的界面弹出时重新问一次；缓存一秒左右没问题。
- **一个请求只带一个落点修饰。** `--in-window=` 和 `--in-tab=` 至多给一个。
- **退出码 1 重试一次，退出码 2 不重试。**
- **管道只读。** 所有动作都走命令行，这样才能和 tessoa 的单实例处理、前台规则保持一致。
